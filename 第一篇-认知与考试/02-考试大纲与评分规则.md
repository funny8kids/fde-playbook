## 2.1 大纲五大模块逐条解读

官方大纲列了五个模块。下面按「考什么 → 怎么考 → 必答要点」拆开。

### 模块 1：大模型基础理论

| 大纲原文关键词 | 实际考法 | 必答要点 |
| --- | --- | --- |
| LLM 基础概念 | 单选：定义、架构、能力边界 | Transformer、自注意力、生成机制 |
| Token | 单选：计量、窗口、计费 | 1 汉字 ≈ 1 Token；窗口有限 |
| Embedding 向量原理 | 单选：性质、相似度 | 语义近 = 向量近；换模型要重建索引 |
| 提示词工程 | 单选：三范式辨析 | Zero-shot / Few-shot / CoT 及适用 |
| 模型幻觉问题 | 单选 + 简答：成因与缓解 | 三类幻觉、五成因、四层缓解 |
| 模型成本评估 | 单选：计算题 | 输入×单价 + 输出×单价 |
| 大模型 API 调用原理 | 单选：参数、流式、限流 | temperature、stream、重试 |

> [!tip] 这一模块的复习方式
> 全部做成「对比表」记忆。凡是两个概念容易混（Token vs 词、RAG vs 微调、temperature vs top_p），就列表。见 [03 章易混点](03-备考策略与答题方法.md#32-30-组易混点（单选题的命门）)。

| 大纲原文关键词 | 实际考法 | 必答要点 |
| --- | --- | --- |
| RAG 完整工作链路 | 简答必考 | 离线五步 + 在线五步，能默画 |
| 文档分块策略 | 单选 + 简答 | 300–500 字、10–20% 重叠、按结构优先 |
| 向量库选型（FAISS、Chroma 等） | 单选：特性对比 | 库 vs 数据库；pre-filter 支持 |

**这一模块的答题结构（背下来）：**

```text
背景与目标 → 架构（解析/分块/向量库/混合检索/重排/生成/引用）
→ 实施六步 → 指标（Recall 0.85 / Faithfulness 0.90 / P95 3s）
→ 风险（幻觉/权限/数据质量/成本）
```

## 2.2 题型与评分逻辑

### 题型结构（以当期考试为准）

| 题型 | 数量（常见） | 单题分值（常见） | 特点 |
| --- | --- | --- | --- |
| 单选题 | 30–50 题 | 1–2 分 | 覆盖面广，考概念细节与辨析 |
| 简答题 | 3–6 题 | 10–20 分 | 考结构、术语、场景结合 |

> [!warning] 说明
> 具体题量与分值以当期考试通知为准。上面给的是「常见结构」，用于安排答题时间，不是官方承诺。

### 简答题的给分逻辑（重要）

阅卷是**找点给分**，不是评作文。所以答案要「点状化」：

| 得分点 | 具体表现 | 常见失分 |
| --- | --- | --- |
| 结构 | 分点、编号、有层次 | 一大段文字，阅卷找不到点 |
| 术语 | 用对专业词（重排、pre-filter、Faithfulness） | 用口语描述，显得不专业 |
| 场景 | 回应题干的特殊约束 | 背通用模板，不结合题干 |
| 数字 | 给出参数与指标 | 只有定性描述 |
| 风险 | 至少两条风险 + 对策 | 只写方案不写风险 |

### 三道「隐形加分项」

1. **主动写指标**：「Recall ≥ 0.85、P95 ≤ 3s」——体现你做过验收；
2. **主动写权限**：「检索前 ACL 过滤 + 生成前二次校验」——体现你懂企业红线；
3. **主动写降级**：「模型超时降级 FAQ、检索失败转人工」——体现你考虑过真实故障。

> [!tip] 一句话
> 同样写 RAG，写了「混合检索 + 重排 + 引用校验 + 评测集 + 权限过滤 + 降级」的人，分数会比只写「用了 RAG 和向量库」的人高一个档次。**不是堆术语，是每个术语都对应一个工程决策。**

## 2.3 命题规律：三种题型的套路

### 套路一：概念辨析题（单选）

题干常出现：「下列关于 X 的说法，**错误/不正确**的是」。
做法：先看有没有「一定/全部/只能/完全」这类绝对词；再用「这个概念解决什么问题」反推。

### 套路二：场景方案题（简答）

题干常出现：「某企业……请给出方案」。
做法：四段式（背景 → 架构 → 步骤 → 风险），每段都写数字。

### 套路三：故障排查题（简答）

题干常出现：「上线后效果不好，请分析原因并给出优化方案」。
做法：按链路归因（数据 → 分块 → 检索 → 重排 → 提示词 → 模型），每段给「怎么验证」。

> [!example] 排查题的万能开头
> 「我会按 RAG 链路逐段定位，而不是直接换模型：先看数据是否解析完整，再看召回是否命中，再看排序是否合理，最后看生成是否忠实。定位后一次只改一个变量并回归评测。」

## 2.5 考前自检清单（打勾才算准备好）

**概念层**
- [ ] 能一句话说清 LLM、Token、Embedding、RAG、Agent 各自解决什么问题
- [ ] 能默画 RAG 两阶段十步
- [ ] 能说出 ReAct 循环与五种失败模式
- [ ] 能区分微调与 RAG 的适用边界

**数字层**
- [ ] 7B FP16 / INT4 显存；KV Cache 公式
- [ ] 分块 300–500 字、重叠 10–20%
- [ ] RRF k=60；召回 50–100 → 重排 20–50 → 生成 3–5
- [ ] 四指标目标值；P95 ≤ 3s
- [ ] 五个法规日期

**方案层**
- [ ] 能 12 分钟内写出四段式简答
- [ ] 能算一次 TCO 与回收期
- [ ] 能说出公有云 / 私有化的四个判断依据
- [ ] 能列上线前 8 条合规动作

**风险层**
- [ ] 幻觉四层缓解
- [ ] 权限三铁律（pre-filter、双校验、审计）
- [ ] 降级路径（模型超时、检索失败、服务不可用）

## 2.6 本章考点速记

> [!success]- 必背 6 条（点击展开自测）
> 1. 五模块权重：RAG 最高，方案设计次之，基础理论单选密集。
> 2. 简答是「找点给分」：结构、术语、场景、数字、风险五维。
> 3. 三个隐形加分项：指标、权限、降级。
> 4. 三种题型套路：概念辨析（防绝对词）、场景方案（四段式）、故障排查（链路归因）。
> 5. 投入比例 ≠ 分值比例：基础理论性价比最高。
> 6. 考前自检四层：概念、数字、方案、风险。

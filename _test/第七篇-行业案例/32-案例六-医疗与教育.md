# 第 32 章 案例六 医疗与教育

> 返回 [全书目录](../00-全书导读与目录.md)。上一篇：[31-案例五-研发代码库](31-案例五-研发代码库.md)；下一篇：[33-案例横向对比与复盘方法](33-案例横向对比与复盘方法.md)。

> [!NOTE]
> **本章解决什么问题**
>
> 一个越界就是医疗风险，一个直接给答案就毁掉教学效果——高风险场景的边界怎么划？
>
> - 写清「本期不做」比写清「本期做」更重要
> - 病历质控要「规则优先、模型补充」
> - 用三级提示替代给答案
>
> **产出**：两套能通过行业审核的边界设计　|　预计 16 分钟


## 32.1 为什么把医疗和教育放在一起

这两个行业的共同点不是技术，是**「用户不专业 + 答错代价高 + 监管要求严」**。它们代表了 AI 落地最难的形态：

| 共性 | 医疗 | 教育 |
| --- | --- | --- |
| 用户不专业 | 患者说不清症状 | 学生问不清知识点 |
| 答错代价高 | 延误就诊、医疗风险 | 学错知识、考试失分 |
| 监管要求严 | 隐私、医疗边界 | 版权、未成年人保护 |
| 正确做法 | **少说、说准、指路** | **不给答案、给方法** |

> [!IMPORTANT]
> **一条跨行业规律**
>
> **越是高风险场景，系统的价值越来自「它拒绝回答了什么」，而不是「它回答了什么」。**
> 这两个案例的全部设计难点，都在「怎么优雅地拒绝并给出正确路径」。

## 32.2 案例六 A：医院就诊指引与病历质控

### 客户与现状

某三甲医院，门诊日均 8000 人次，导诊台 6 人，重复咨询占 70%；同时医务科需抽查病历书写规范（每月 500 份，每份 15 分钟）。

| 现状数据 | 数值 | 问题 |
| --- | --- | --- |
| 日均门诊量 | 8000 人次 | 导诊台压力集中在上下午高峰 |
| 导诊台人力 | 6 人 | 70% 是重复问题（科室在哪、要带什么） |
| 病历抽检 | 500 份/月 × 15 分钟 | 约 125 工时/月，且靠人工翻 |
| 患者年龄结构 | 60 岁以上占 38% | 打字困难，看不清小字 |
| 投诉热点 | 「不知道该挂哪个科」 | 挂错科导致退号重挂 |

**注意这是两条完全不同的链路**：导诊面向患者（对外、口语、高风险边界），质控面向医生（对内、结构化、效率导向）。**它们共用一套基础设施，但业务逻辑必须分开。**

### 需求澄清：三条边界先划清

| 轮次 | 客户说 | 你追问 | 澄清结果 |
| --- | --- | --- | --- |
| 1 | 「能帮患者判断是什么病」 | 「判断错了谁负责？」 | **不做诊断**，只做「症状 → 科室」指引 |
| 2 | 「能推荐挂哪个专家」 | 「专家排班天天变，谁维护？」 | 不做推荐，只给科室 + 挂号入口跳转 |
| 3 | 「能自动改病历」 | 「改了之后责任在谁？」 | **不改病历**，只做「缺项/规范提醒」，医生确认 |

三条边界写成方案里的「本期不做」：

```text
本期不做：疾病诊断、用药建议、专家推荐、病历自动修改
本期做：症状→科室指引、就诊流程、材料清单、病历规范提醒、缺项标注
必须做：免责声明、转人工入口、全量审计、数据不出院
```

> [!WARNING]
> **「本期不做」这一节比「本期做」更重要**
>
> 医疗项目的失败，80% 死在越界。**在方案第一页写清边界，等于给自己上了一道保险**——后面任何人提越界需求，你都可以指着这一页说「这不在范围内」。

### 约束清单

| 约束 | 具体 | 对方案的影响 |
| --- | --- | --- |
| 合规 | 患者隐私，数据不出院内 | 全私有化，模型与向量库本地部署 |
| 医疗边界 | 不能给诊断建议 | 只做「指引」，明确免责与转诊 |
| 用户 | 口语化、老年用户多（38%） | 语音输入 + 大字号 + 简洁输出 |
| 准确性 | 科室指引错会延误就诊 | 强引用 + 人工维护知识库（医务科审核） |
| 审计 | 医务质控需留痕 | 全量日志与会话存档，≥3 年 |

### 被否决的两个方案

| 方案 | 否决理由 |
| --- | --- |
| A 接入在线问诊大模型（含诊断能力） | 越界，**医疗边界不允许**；且无法承担误诊责任 |
| B 病历质控直接由模型改写 | 责任主体不清，医生不接受「系统改我的病历」 |

### 双链路架构

**链路一：患者导诊**

| 层 | 设计 | 关键参数 |
| --- | --- | --- |
| 输入 | 语音为主 + 症状选项（不用自由文本） | 老年用户占比 38%，必须支持语音 |
| 理解 | 症状 → 科室映射表（医务科维护，约 800 条） | 映射表是核心资产，不是模型 |
| 检索 | 症状描述向量检索 + 科室关键词匹配 | 召回 20 → 重排 Top3 |
| 输出 | 「建议挂 XX 科 + 位置 + 挂号入口 + 免责声明」 | 不给病因、不给用药 |
| 兜底 | 置信度 <0.6 或涉及急症关键词 → 直接提示「请到急诊/导诊台」 | 急症词表 120 条 |

**链路二：病历质控**

| 层 | 设计 | 关键参数 |
| --- | --- | --- |
| 输入 | 电子病历结构化字段 + 自由文本 | 从 HIS 导出，脱敏后处理 |
| 规则 | 规则引擎（必填项、时限、逻辑一致性）+ 模型（表述规范性） | **规则优先，模型补充** |
| 输出 | 「缺项清单 + 规范建议 + 原文定位」 | 只提醒，不改写 |
| 复核 | 医务科人工复核队列 | 高误报项人工确认后再推送 |

> [!TIP]
> **为什么质控要「规则优先」**
>
> 病历质控的 70% 问题是「必填项缺失」「时限超期」这类**确定性规则**，用规则引擎准确率 100%、成本几乎为零。
> 只有「表述是否规范」这类才需要模型。**先规则后模型，能省一半成本，还能把误报率压下来。**

### 关键调优

| 问题 | 现象 | 解法 | 效果 |
| --- | --- | --- | --- |
| 老年用户不用 | 上线首月使用率不足 10% | 加语音输入 + 大字版 + 导诊台人员引导 | 使用率 35% |
| 越界风险 | 出现「您可能是XX病」 | 提示词 + 输出后置过滤（疾病名词表拦截） | 越界输出 0 |
| 质控误报高 | 规则照搬条文，误报 40% | 拆「必填/选填」+ 人工复核队列 | 误报 12% |
| 急症漏判 | 「胸闷」被当成普通症状 | 急症词表 120 条，命中即强制提示急诊 | 漏判 0 |

### 指标结果

| 指标 | 上线前 | 上线后 | 测量方法 |
| --- | --- | --- | --- |
| 导诊台重复咨询 | 70% | 下降约 45% | 导诊台计数抽样 |
| 挂错科退号率 | 8.2% | 5.1% | HIS 退号原因统计 |
| 病历抽检工时 | 125 工时/月 | 45 工时/月 | 医务科工时记录 |
| 质控缺项发现率 | 人工 62% | 规则+模型 89% | 与专家标注比对 |
| 越界输出 | — | 0 条 | 抽检 500 条 + 关键词拦截日志 |
| 老年用户使用率 | — | 35% | 分年龄段埋点 |

### 成本与商务

| 项 | 金额 | 说明 |
| --- | --- | --- |
| 私有化硬件 | 45 万 | 院内机房，含存储 |
| 实施人力 | 12 人月 × 3.2 万 = 38.4 万 | 两条链路 |
| 数据工程 | 4 人月 × 2.8 万 = 11.2 万 | 症状映射表 + 病历标注 |
| 等保与测评 | 8 万 | 医疗行业要求高 |
| 培训与文档 | 5 万 | 导诊台 + 医务科分别培训 |
| 首年运维 | 16 万 | 含映射表维护 |
| 成本小计 | 123.6 万 | |
| 管理费 15% | 18.5 万 | |
| 报价（毛利 33%） | **212 万** | 年运营费 18 万/年 |

### 踩过的三个坑

| # | 坑 | 后果 | 改法 |
| --- | --- | --- | --- |
| 1 | 一开始允许「健康建议」 | 出现越界风险，被医务科叫停 | 只做指引、不做判断 + 疾病名词表拦截 |
| 2 | 忽略老年用户 | 上线首月使用率不足 10% | 语音 + 大字版 + 现场引导 |
| 3 | 质控规则照搬条文 | 误报率 40%，医生抵制 | 拆必填/选填 + 人工复核队列 |

## 32.3 案例六 B：职业教育机构智能助教

### 客户与现状

某职业教育机构，200 门课程、3 万道题库、每年 2 万名学员。助教 30 人，重复答疑（报名、课程安排、作业规则）占 60%。

| 现状数据 | 数值 | 问题 |
| --- | --- | --- |
| 年学员 | 2 万人 | 峰值集中在开课与考试周 |
| 助教 | 30 人 | 60% 时间在答重复问题 |
| 平均答疑等待 | 4 小时 | 夜间提问要等到次日 |
| 题库 | 3 万道 | 有解析，但学员搜不到相似题 |
| 课程资料 | 200 门 | 版权敏感，不能外泄 |

### 需求澄清：一个对抗性问题

| 轮次 | 客户说 | 你追问 | 澄清结果 |
| --- | --- | --- | --- |
| 1 | 「学员问作业，直接给答案」 | 「给了答案他学会了吗？续费率会怎样？」 | 客户改口：**不给答案，给思路** |
| 2 | 「那给个提示就行」 | 「学员会连续追问『再提示一点』吗？」 | 需要**分级提示**（3 级，逐级展开） |
| 3 | 「夜间也要答」 | 「夜间流量占比多少？愿意为此付多少？」 | 夜间 22:00–8:00 占 28%，切小模型即可 |

三级提示的设计（这是教育场景的核心产品设计）：

```text
L1 提示：指出考查的知识点（「这道题考的是二叉树的中序遍历」）
L2 提示：给出解题思路（「先递归左子树，再访问根，最后右子树」）
L3 提示：给出关键步骤（不含完整代码/完整答案）
超纲或连续追问 3 次仍不会 → 转人工，并标记为「学习困难」推送助教
```

> [!IMPORTANT]
> **为什么是三级而不是直接给答案**
>
> 学员的直接诉求一定是「给我答案」，但**客户的商业诉求是「学员学会、续费」**。
> 这两者冲突时，要服从客户的商业诉求——这是 FDE 与「做个好用工具」的区别。**你要替客户做他不方便做的那个决定。**

### 约束清单

| 约束 | 具体 | 影响 |
| --- | --- | --- |
| 内容 | 课程资料有版权 | 不能外泄，需权限控制 + 防抓取 |
| 准确性 | 讲错知识点会误导学员 | 强引用教材 + 不自由发挥 |
| 体验 | 学员随时提问（含夜间） | 7×24 可用，响应快 |
| 成本 | 学员规模大，单次成本敏感 | 模型分级 + 语义缓存 |
| 合规 | 部分课程涉及未成年人 | 内容安全更严格（输入输出双向过滤） |

### 被否决的两个方案

| 方案 | 否决理由 |
| --- | --- |
| A 直接给答案 + 解析 | 客户明确反对（影响续费与口碑），且助教强烈抵制 |
| B 全部转人工 | 夜间无法覆盖，且成本没降 |

### 架构要点

| 模块 | 设计 | 关键参数 |
| --- | --- | --- |
| 知识库 | 课程大纲、讲义、FAQ、作业规则；按「课程—章节」分块 | 课程 ID 作为硬过滤 |
| 题库 | 题目 + 解析结构化入库；支持相似题推荐 | 相似度阈值 0.85 |
| 答疑 | RAG 问答 + 引用教材页码；超纲转人工 | 引用准确率目标 ≥0.90 |
| 学习助手 | 基于错题生成练习计划（**模板化，不自由生成**） | 模板 12 套 |
| 内容安全 | 输入输出双向过滤；未成年人场景更严格 | 敏感词库 + 模型审核 |
| 成本 | 简单问题小模型；高频 FAQ 语义缓存；夜间切小模型 | 缓存命中 31% |

### 关键调优

| 问题 | 现象 | 解法 | 效果 |
| --- | --- | --- | --- |
| 学员套答案 | 「这题答案是什么」 | 三级提示 + 不输出完整答案 | 套答案请求下降 76% |
| 教材版本更新 | 旧版内容仍在答 | 元数据带版本与生效日期，旧版下线 | 版本错误 0 |
| 跨课程串答 | A 课程学员查到 B 课程资料 | 课程 ID 硬过滤 | 串答 0 |
| 夜间成本高 | 夜间占 28% 流量但用大模型 | 低峰切小模型 + 缓存 | 成本降 60% |

### 指标结果

| 指标 | 上线前 | 上线后 | 测量方法 |
| --- | --- | --- | --- |
| 助教重复答疑量 | 基线 | 下降 55% | 工单分类统计 |
| 学员平均等待 | 4 小时 | 30 秒 | 会话时间戳 |
| 答疑准确率 | — | 91% | 抽检 300 条 |
| 单次答疑成本 | 2 元（人工） | 0.25 元 | 总成本/会话数 |
| 续费率 | 基线 | +3.2 pt | 与对照组比较 |

### 成本与商务

| 项 | 金额 | 说明 |
| --- | --- | --- |
| 实施人力 | 6 人月 × 3.0 万 = 18 万 | |
| 数据工程 | 2 人月 × 2.6 万 = 5.2 万 | 题库结构化 + FAQ 挖掘 |
| 模型调用（年） | 8 万 | 含夜间小模型 |
| 首年运维 | 6 万 | |
| 成本小计（首年） | 37.2 万 | |
| 报价（毛利 35%） | **57 万（首年）** | 次年起 16 万/年 |

### 踩过的三个坑

| # | 坑 | 后果 | 改法 |
| --- | --- | --- | --- |
| 1 | 直接给答案 | 学员投诉「学不到东西」 | 改为「思路 + 知识点 + 相似题」 |
| 2 | 没做课程隔离 | A 课程学员查到 B 课程资料 | 课程 ID 硬过滤 |
| 3 | 夜间用大模型 | 成本超预算 | 分级 + 缓存，降 60% |

## 32.4 医疗与教育横向对比

| 维度 | 医疗 | 教育 |
| --- | --- | --- |
| 核心约束 | 隐私 + 医疗边界 | 版权 + 内容安全 |
| 最大风险 | 越界诊断 | 讲错知识 / 直接给答案 |
| 关键设计 | 只做指引 + 免责 + 转诊 | 给思路不给答案 + 课程隔离 |
| 用户特点 | 老年多（38%）、口语化 | 年轻、夜间活跃（28%） |
| 部署 | 全私有化 | 云服务 |
| 成本结构 | 硬件重（45 万）、人力重 | 模型费重、人力轻 |
| 一句话经验 | **边界比能力重要** | **教学法比模型重要** |

## 32.5 高风险行业的五条共性

这两个案例的约束看起来不同，但设计上有五条完全一致：

| # | 共性 | 医疗怎么做 | 教育怎么做 |
| --- | --- | --- | --- |
| 1 | **拒答策略** | 置信度 <0.6 转导诊台；急症词表直接提示急诊 | 超纲转人工；连续追问 3 次标记困难 |
| 2 | **免责与边界声明** | 每屏显示「本内容不构成诊疗建议」 | 每屏显示「请以教材与教师讲解为准」 |
| 3 | **人工兜底** | 导诊台 + 医务科 | 助教 + 教师 |
| 4 | **全量审计** | 会话存档 ≥3 年 | 会话存档 + 内容安全日志 |
| 5 | **输出可追溯** | 引用科室指引条目 | 引用教材页码 + 版本 |

> [!IMPORTANT]
> **这五条可以直接迁移**
>
> 遇到任何一个高风险行业（法务、保险、证券、心理），先把这五条列进方案，再谈技术选型。
> **在高风险场景里，「怎么不出事」是方案的第一章，不是附录。**

## 32.6 本章考点速记

<details>
<summary><b>折叠背诵版</b></summary>

> **医疗三线**：只做指引不做诊断、数据不出院、输出可追溯。
> **医疗两链路**：患者导诊（症状→科室映射表 800 条 + 急症词表 120 条）与病历质控（**规则优先 + 模型补充 + 人工复核**）。
>
> **教育核心**：给思路不给答案（**三级提示**）、课程 ID 硬过滤、版本时效、内容安全双向过滤。
>
> **高风险五共性**：拒答策略、免责声明、人工兜底、全量审计、输出可追溯。
>
> **指标**：医疗——重复咨询降 45%、退号率 8.2%→5.1%、质控工时 125→45、越界 0；
> 教育——重复答疑降 55%、等待 4 h→30 s、准确率 91%、成本 2 元→0.25 元。
>
> **一句话**：高风险场景，价值来自「拒绝得对」，不是「答得多」。

</details>

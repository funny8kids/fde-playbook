## 41.1 一、公式速查

```text
# 成本
单次成本 = 输入Token × 输入单价 + 输出Token × 输出单价
月成本   = 日请求数 × 30 × 单次成本
年成本   = 月成本 × 12

# 检索融合
RRF 分数 = Σ 1 / (k + rank_i)          k 常取 60

# 显存
显存 ≈ 权重 + KV Cache + 运行时开销(1–2GB)
权重 = 参数量 × 每参数字节（FP16=2, INT8=1, INT4≈0.5）
KV Cache = 2 × 层数 × KV头数 × 头维度 × 序列长度 × 并发 × 字节

# 容量
峰值 QPS = 日请求 × 集中时段占比 ÷ (集中小时 × 3600)
并发 = 峰值 QPS × 单请求耗时
卡数 = 并发 ÷ 单卡可承载并发 × 1.3

# 商务
私有化划算：公有云年费 > 私有化年成本 × 1.3
静态回收期 = 项目投入 ÷ (年收益 − 年运营成本)
ROI = (年收益 − 年成本) ÷ 项目投入

# 评测
Recall@K    = 命中的黄金块 ÷ 全部黄金块
Precision@K = 相关块 ÷ 召回块
```

### 清单 1：需求调研（27 问）

## 41.4 四、提示词模板库（10 个）

### 1. RAG 问答（通用）

```text
你是{企业}{部门}知识助手。依据【资料】回答【问题】，资料是唯一事实来源。
【资料】<<<CONTEXT [1] {chunk_1}（{title} 第{page}页） … CONTEXT>>>
【问题】<<<QUESTION {question} QUESTION>>>
要求：只用资料；每条结论标 [编号]；资料不足回答「无法确定，建议咨询{部门}」；
数字日期原文照抄；输出「结论 / 依据 / 步骤 / 风险提示」。
```

### 2. 结构化抽取

```text
从文本抽取字段，严格按 JSON Schema 输出，不要解释；缺失填 null，不得编造。
Schema: {"party_a":string,"party_b":string,"amount":number,"sign_date":"YYYY-MM-DD"}
文本：<<<DOC {doc} DOC>>>
```

### 3. 分类路由

```text
判断问题类别，只输出类别名：售前/售后/物流/投诉/其他。
规则：价格方案→售前；退换维修→售后；快递签收→物流；不满赔偿→投诉。
问题：{question}
```

### 4. 摘要压缩

```text
把对话压缩为「事实清单 + 未完成事项」，不超过 200 字，保留数字与专有名词。
对话：{history}
```

### 5. 查询改写

```text
把用户问题改写为适合检索的查询，输出 3 条，每行一条，不要解释。
要求：消解指代、补全同义词、保留型号与编号。
问题：{question}  上文：{last_turns}
```

### 6. 引用校验

```text
判断回答中的每个 [编号] 是否能在资料中找到对应内容。
输出 JSON：[{"claim":"...","cite":"[1]","supported":true/false}]
资料：{context}  回答：{answer}
```

### 7. 拒答判定

```text
判断问题是否在业务范围内（{scope}）。输出：IN_SCOPE / OUT_OF_SCOPE + 一句理由。
问题：{question}
```

### 8. 工具调用规划

```text
可用工具：{tools}
任务：{task}
输出执行计划：每步「用哪个工具、什么参数、为什么」，最多 5 步。
若信息不足，先列出需要向用户确认的问题。
```

### 9. 答案自检

```text
先给答案，再自查：①是否只用资料？②是否都有引用？③数字日期是否与原文一致？④是否回答了真正的问题？
不符则修正后重新输出。
```

### 10. 话术生成（带合规约束）

```text
生成营销话术，要求：不承诺收益、不使用绝对化用语、必须包含风险提示。
产品信息：{product}  目标客户：{segment}  字数：{n}
```

## 41.5 五、代码片段

### 1. RAG 主流程

```python
def answer(question, user):
    q = rewrite(question, history)
    qv = embed(q)
    flt = {"dept": {"$in": user.depts}, "visibility": {"$lte": user.level},
           "effective_date": {"$lte": today()}}
    dense = vdb.search(qv, top_k=40, filter=flt)
    sparse = bm25.search(q, top_k=40, filter=flt)
    fused = rrf([dense, sparse], k=60)[:20]
    ranked = rerank(q, fused)[:5]
    if not ranked or ranked[0].score < 0.3:
        return refuse()
    ctx = "\n".join(f"[{i+1}] {r.text}（{r.title} 第{r.page}页）" for i, r in enumerate(ranked))
    return llm(PROMPT.format(context=ctx, question=question), temperature=0.2, stream=True)
```

### 2. 增量索引

```python
for doc in scan(source):
    h = sha256(doc.content)
    if h == db.get_hash(doc.id):
        continue
    chunks = split(parse(doc))
    vdb.delete_by_doc(doc.id)
    vdb.upsert(embed(chunks))
    db.set_hash(doc.id, h)
```

### 3. Agent 循环（带护栏）

```python
while steps < MAX_STEPS and used < BUDGET:
    resp = llm(messages, tools=TOOLS, temperature=0.2)
    used += resp.usage.total_tokens
    if not resp.tool_calls:
        return resp.content
    for call in resp.tool_calls:
        if call.name not in ALLOWED: result = {"error_code": "TOOL_NOT_ALLOWED"}
        elif not has_permission(user, call.name, call.args): result = {"error_code": "FORBIDDEN"}
        elif is_write(call.name) and not confirmed(user, call): result = {"error_code": "NEED_CONFIRM"}
        else: result = safe_execute(call.name, call.args)
        messages.append(tool_result(call.id, sanitize(result)))
    steps += 1
return "需要人工介入，已创建工单。"
```

### 4. 引用后置校验

```python
def verify_citations(answer, chunks):
    for m in re.findall(r"\[(\d+)\]", answer):
        idx = int(m) - 1
        if idx < 0 or idx >= len(chunks):
            return False
    return True
```

## 41.6 六、计算题十道（带完整解）

考试与面试最爱考计算。这十道覆盖 90% 的考法，建议手算一遍。

**题 1** 7B 模型 FP16 部署，上下文 4096，并发 8，KV 结构 32 层 / 8 KV 头 / 头维 128。显存需要多少？

> 权重 = 7B × 2 B = 14 GB
> 每 Token KV = 2 × 32 × 8 × 128 × 2 B = 128 KB
> KV 总量 = 128 KB × 4096 × 8 = 4.0 GB
> 运行时 1.5 GB
> **合计 ≈ 19.5 GB → 单张 24 GB 卡可跑，余量 4.5 GB（约 18%）**

**题 2** 同上，改成 INT4 量化、上下文 16384、并发 12，还能跑单张 24 GB 吗？

> 权重 ≈ 3.5 GB（INT4 约 0.5 B/参数，含少量非量化层按 0.55 估）
> KV = 128 KB × 16384 × 12 = 24 GB ← **已超单卡**
> 结论：不行。要么把并发降到 8（16 GB），要么用 KV 量化（减半 → 8 GB，可跑）。

**题 3** 日活 3000，人均 6 次，75% 集中在 5 小时，平均单请求 5 s。峰值 QPS 与并发是多少？

> 日请求 = 18000
> 峰值 QPS = 18000 × 0.75 ÷ (5 × 3600) = 0.75
> 并发 = 0.75 × 5 ≈ 3.75 → 取 5

**题 4** 承接题 3，单卡实测安全并发 10，需要几张卡？

> 卡数 = 5 ÷ 10 × 1.3 = 0.65 → 向上取整 1 张；考虑容灾 → **2 张**

**题 5** RAG 单次请求：系统提示 800 Token、检索片段 5 段 × 600 Token、历史 400 Token、输出 500 Token。中杯模型输入 0.004 元/千 Token、输出 0.012 元/千 Token，单次成本多少？

> 输入 = 800 + 3000 + 400 = 4200 Token = 4.2 千
> 输入成本 = 4.2 × 0.004 = 0.0168 元
> 输出成本 = 0.5 × 0.012 = 0.006 元
> **单次 ≈ 0.0228 元**；日均 5000 次 → 年成本 ≈ 4.16 万元

**题 6** 若把检索片段从 5 段压到 3 段，成本降多少？代价是什么？

> 输入变为 800 + 1800 + 400 = 3000 Token → 成本 0.012 + 0.006 = 0.018 元
> 降幅 = (0.0228 − 0.018) / 0.0228 ≈ **21%**
> 代价：Context Recall 可能下降（少给 2 段依据），必须用黄金集验证是否仍达门禁。

**题 7** 客户年 API 成本 42 万元；私有化硬件 76 万元（5 年折旧）、年运维人力 15.6 万元、年电费 4.2 万元。该转私有化吗？

> 私有化年成本 = 76/5 + 15.6 + 4.2 = 35.0 万元
> 拐点阈值 = 35.0 × 1.3 = 45.5 万元
> 42 < 45.5 → **暂不转**；若用量再涨 10% 以上则跨过拐点。

**题 8** 项目成本 186.8 万元，目标毛利率 35%，报价应为多少？若客户压价 15%，毛利率变成多少？

> 报价 = 186.8 ÷ (1 − 0.35) = **287.4 万元**
> 压价后 = 287.4 × 0.85 = 244.3 万元
> 毛利 = (244.3 − 186.8) / 244.3 ≈ **23.5%** → 已低于健康线（30%），应考虑缩范围而非降价。

**题 9** 黄金集 100 题，模型 A 答对 84 题、模型 B 答对 88 题。能否判定 B 更好？

> 差 4 个百分点，n=100。按二项分布，差值的标准误 ≈ √(2×0.5×0.5/100) ≈ 7.1 pt
> 4 pt < 7.1 pt → **统计上不显著**。
> 结论：按成本与可控性选，不要按这 4 分选。

**题 10** 文档 8000 份、共 24 万页，解析产能 3 万页/人月，抽检返工按 15% 计。需要多少数据工程人月？

> 基础 = 24 / 3 = 8 人月
> 返工 = 8 × 0.15 = 1.2 人月
> 另加清点 1 人月、元数据 2 人月、抽检 1.5 人月
> **合计 ≈ 13.7 人月**（若含 OCR 与人工校对，按 43.6 的口径可达 18 人月）

## 41.7 七、验收指标模板库（按场景抄）

| 金融合规问答 | 引用准确率 / 版本正确率 / 越权率 / 拒答恰当率 | 0.95 / **1.00** / **0** / 0.85 | 300 题 + 三类账号交叉测试 |
| 制造手册问答 | 一次解决率 / 步骤完整率 / 溯源率 / 型号匹配率 | 0.70 / 0.98 / 1.00 / 0.98 | 工单回访 + 抽检 200 条 |

| 政务知识库 | 政策引用准确率 / 标识覆盖率 / 自助率 / P95 | 0.95 / **1.00** / 0.60 / ≤8 s | 抽检 300 条 + 三处核查 |
| 医疗导诊 | 科室指引准确率 / 越界输出 / 拒答恰当率 / 老年可用性 | 0.90 / **0** / 0.85 / 抽测通过 | 专家标注 + 抽检 500 条 |
| 教育助教 | 答疑准确率 / 套答案拦截率 / 课程隔离 / 内容安全 | 0.90 / 0.95 / **0 串答** / **0 违规** | 抽检 300 条 + 攻击测试 |

> [!IMPORTANT]
> **加粗的三个「0 和 1」**
>
> 越权率、版本正确率、标识覆盖率、内容违规——这四项在强监管场景里**没有区间，只有达标与不达标**。
> 方案里写成「≥95%」，评委会认为你不懂这个行业。

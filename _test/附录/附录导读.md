正文是「读一遍」的，附录是「**反复查**」的。五个附录对应五种查阅场景：

| 附录 | 内容 | 什么时候翻 |
| --- | --- | --- |
| [40-附录A-术语表](40-附录A-术语表.md) | 160 条术语（技术 120 + 工程商务 40） | 客户会、跨部门沟通、看不懂对方用词 |
| [41-附录B-公式清单与模板库](41-附录B-公式清单与模板库.md) | 公式、参数、清单、10 个提示词模板、4 段代码、10 道计算题带解 | 现场算数、写方案、考前手算 |

| [43-附录D-行业指标基准库](43-附录D-行业指标基准库.md) | 80+ 项指标基准与阈值 | 定验收指标、判断「还差多少」 |

> [!IMPORTANT]
> **一句话**
>
> **正文给你方法，附录给你「凭据」。** 客户问「这个数字哪来的」，能翻到一页给出处的人，和只能说「经验上大概」的人，是两个层级。

## 怎么用（三个具体场景）

**场景一：定验收指标**

```text
12.6 上线门禁（方法） → 43.1 指标基准（数字） → 41.7 验收指标模板（写法）
三步得到一句能写进合同的话：
「以 100 题测试集为基准，业务专家判定：Context Recall ≥0.85、Faithfulness ≥0.90、
  引用准确率 ≥0.94、拒答恰当率 ≥0.85；任一项不达标进入 15 个工作日整改，复测一次。」
```

**场景二：现场被问住**

| 客户问 | 翻 |
| --- | --- |
| 「这个准确率算高还是低？」 | 43.1 / 43.2 |
| 「7B 模型要几张卡？」 | 41.1 公式 → 24.8 算例 |
| 「你们说的 RAG 和我们说的知识库是一回事吗？」 | 40.1 术语对照 |
| 「凭什么说这个方案可行？」 | 42.7 十篇必读（一句话结论） |

**场景三：考前 3 天**

```text
37 速记册（唤醒）→ 41.6 十道计算题（手算一遍）→ 43.9 指标速查卡（打印版）
```

## 附录的使用纪律

> [!WARNING]
> **三条要注意**
>
> ① **附录里的数字都是「经验区间」，不是标准。** 43.0 明确说了：没有任何行业标准规定「Context Recall 必须 ≥0.85」，它是实践共识，用于内部判断「还差多少」，不能作为唯一验收依据。
>
> ② **法规以标注的施行日为准，价格与榜单以签约时为准。** 这两类信息变化最快，书中数字只作量级参考。
>
> ③ **公式要会用，不只是会看。** 41.6 那十道题建议真的手算一遍——面试和客户会上，能当场算出来的人立刻区分于其他人。

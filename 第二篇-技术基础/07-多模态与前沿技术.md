# 第 7 章 多模态与前沿技术

> 返回 [全书目录](../00-全书导读与目录.md)。上一篇：[06-微调对齐与模型轻量化](06-微调对齐与模型轻量化.md)；下一篇：[08-模型选型与能力评测](08-模型选型与能力评测.md)。

> [!NOTE]
> **本章解决什么问题**
>
> 客户开始提「能不能识别图片」「能不能看视频」「能不能听录音」——你要能判断**能不能做、怎么做、坑在哪**。
> 本章不追热点，只讲企业落地时会遇到的多模态能力边界，以及 2024–2026 年值得关注的四个方向。

---

## 7.1 多模态能力地图

| 模态 | 典型任务 | 成熟度 | 企业落地难点 |
| --- | --- | --- | --- |
| 图像理解（VLM） | 单据识别、缺陷检测、图纸问答 | 较高 | 小字、模糊、专业符号 |
| 图像生成 | 营销素材、示意图 | 高（创意）/ 低（精确） | 文字渲染、事实一致性 |
| 语音识别（ASR） | 会议记录、客服录音 | 高 | 方言、噪声、专业术语 |
| 语音合成（TTS） | 播报、客服 | 高 | 情感、多音字 |
| 视频理解 | 监控分析、培训视频检索 | 中 | 长视频切片、时序理解 |
| 文档视觉（OCR+版面） | 扫描件、表格、票据 | 高 | 表格结构、手写体 |

> [!IMPORTANT]
> **判断原则**
>
> **先问「错了会怎样」。** 缺陷检测错一个可能停产，单据识别错一个字段可以人工复核——两者对精度的要求差一个数量级，方案也完全不同。

---

## 7.2 视觉理解（VLM）在 RAG 里的位置

三种集成方式，按复杂度递增：

| 方式 | 做法 | 适用 | 代价 |
| --- | --- | --- | --- |
| 图片转文字 | 先 OCR / 图注，再走文本 RAG | 单据、截图、扫描件 | 丢失版面与图表语义 |
| 多模态 Embedding | 图文映射到同一向量空间，直接检索 | 图文混排知识库 | 模型选择少、效果需验证 |
| 多模态生成 | 检索到图片后，把图片一起送入 VLM 作答 | 图纸问答、故障图片诊断 | Token 成本高、延迟大 |

> [!TIP]
> **工程建议**
>
> 企业知识库 80% 的图片需求，用「OCR + 图注 + 文本 RAG」就能满足，成本最低、可控性最好。只有当问题本身依赖「视觉细节」（如「这个接口在板的哪一侧」），才值得上多模态生成。

## 7.3 语音链路：ASR → LLM → TTS

```text
用户语音 → ASR 转文字 → （可选：意图路由）→ RAG/LLM → TTS 播报
```

| 环节 | 关键指标 | 常见问题 |
| --- | --- | --- |
| ASR | 字错率 CER | 方言、噪声、专业术语错 |
| LLM | 首 Token 延迟 | 长回答导致等待 |
| TTS | 首包延迟 | 播报生硬、数字读法错 |

工程要点：

1. **术语表**：把设备名、药名、型号加入 ASR 热词，字错率能降一大截；
2. **流式三段**：ASR 出中间结果就开始检索，TTS 边生成边播，体感延迟减半；
3. **打断处理**：用户中途说话要能中断播报（VAD + 状态机）。

## 7.4 四个值得关注的方向

### 方向一：推理增强模型

特征：在回答前进行较长的内部推理（thinking），在数学、代码、多步规划上明显更强。
对企业的影响：

- 适合：复杂规则判断、多步计算、方案推演；
- 不适合：高频简单问答（成本与延迟不划算）；
- 工程做法：**分级路由**——简单问题走普通模型，复杂问题才走推理模型。

### 方向二：长上下文与「上下文工程」

窗口从 32K 涨到百万级，但**不是让你把所有资料都塞进去**：

| 用法 | 是否合理 |
| --- | --- |
| 一次性读完整份合同/年报 | 合理（省去分块与检索） |
| 把整个知识库塞进上下文做问答 | 不合理（成本极高、中间内容易被忽略） |
| 长上下文 + 检索结合 | 最合理（先检索定位，再用长窗口读整章） |

### 方向三：Agentic RAG

让 Agent 自己决定「要不要检索、检索几次、换什么查询」。适合复杂多跳问题，代价是延迟与成本上升。判断标准：**单次检索能否解决？不能，才上 Agentic。**

### 方向四：端侧与小模型

量化 + 蒸馏让小模型跑在笔记本/工控机上。适合：数据极度敏感、离线环境、低延迟要求。代价：能力上限受限，复杂任务仍需云端。

## 7.5 前沿技术的评估框架（别被 PPT 忽悠）

看到一个新模型/新框架，用五个问题判断值不值得引入：

| 问题 | 为什么问 |
| --- | --- |
| 它解决的是我哪个具体痛点？ | 避免「为了用而用」 |
| 在我自己的评测集上提升多少？ | 榜单 ≠ 你的场景 |
| 成本与延迟变化多少？ | 效果 +10% 但成本 ×3 可能不划算 |
| 部署与运维复杂度增加多少？ | 引入一个新组件就是一份运维债 |
| 出问题能回滚吗？ | 不能回滚的技术不进生产 |

> [!WARNING]
> **反模式**
>
> 「因为这个模型榜单第一，所以我们换掉现有方案。」——没有在自己的数据上验证过的替换，都是赌博。

## 7.6 多模态项目的成本直觉

| 环节 | 成本特征 |
| --- | --- |
| 图片理解 | 按图片计费或折算 Token，通常显著高于纯文本 |
| 视频理解 | 抽帧后按图片计费，长视频成本很高 |
| 语音 | ASR 按音频时长，TTS 按字符 |
| 存储 | 原图/原视频占空间，需对象存储与生命周期策略 |

优化手段：抽帧降采样、图片压缩到必要分辨率、只对关键帧做理解、结果缓存。

## 7.7 VLM 的四个真实局限（别在演示里翻车）

多模态演示很容易惊艳，上线后却问题不断。四个稳定的短板：

| 局限 | 表现 | 影响 | 应对 |
| --- | --- | --- | --- |
| **精细计数** | 数不清图里有 13 个人还是 14 个 | 盘点、质检类场景不可用 | 用专用检测模型，不用 VLM 数 |
| **小字识别** | 表格里的 8 号字、票据编号读错 | 票据/单据类错误率高 | 先用 OCR，再让模型理解结构 |
| **空间关系** | 「A 在 B 的左边」经常判反 | 装配、图纸类场景出错 | 需要精确定位时用检测框坐标 |
| **多图一致性** | 给两张图比较差异，会「脑补」不存在的内容 | 比对类任务不可靠 | 分别描述后结构化比对，不让模型直接判 |

> [!WARNING]
> **一条实战建议**
>
> **演示时不要用「数一数」「读小字」「判断左右」这三类问题**——它们是 VLM 最不稳的地方，一旦翻车，客户对整个方案的信任都会打折。
> 演示要选「理解整体语义」的任务：这张图是什么、这段视频讲了什么、这份扫描件属于哪类文档。

## 7.8 多模态 RAG 的三种工程形态

文档里既有文字又有图（表格截图、流程图、产品照片），怎么进知识库？三种做法：

| 形态 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| **① 图转文** | 用 VLM 把图描述成文字，只索引文字 | 简单、成本低、复用现有链路 | 细节丢失（坐标、数值） | 图片以示意图为主 |
| **② 图文双索引** | 图单独向量化（CLIP 类），文本单独索引，检索后合并 | 支持「以图搜图」 | 两套索引、融合复杂 | 有图片检索需求 |
| **③ 多模态原生** | 图文一起送入多模态模型，不做分离 | 保留版面与空间信息 | 成本高、延迟大、上下文受限 | 票据、报表、图纸 |

**推荐的务实路线**：

```text
默认：① 图转文（覆盖 80% 场景）
  └─ 表格/票据类：先 OCR 出结构，再让模型理解（不是纯图转文）
需要搜图时：② 图文双索引
高价值少量文档：③ 原生多模态（如合同扫描件、工程图纸）
```

> [!TIP]
> **一个被低估的做法**
>
> **给图片生成「结构化描述」而不是「自然语言描述」**。
> 差： 「这是一张设备参数表。」
> 好： 「表名：A 型泵参数；列：型号/流量/扬程/功率；行数：6；关键值：A-100 流量 100m³/h、扬程 32m。」
> 后者能被检索命中，前者只能被「猜」。

## 7.9 语音链路的体验细节：决定「像不像人」

语音项目的技术指标（ASR 准确率）往往达标，但用户体验差，问题都在这几个细节：

| 细节 | 做错的表现 | 正确做法 |
| --- | --- | --- |
| **VAD（断句）** | 用户稍一停顿就被打断 | 静音阈值 600–800 ms，可配置 |
| **打断（Barge-in）** | 用户说话时 TTS 还在播 | 检测到人声立即停止播报 |
| **首响** | 等 3 秒才出声 | 先说「我看看」，再异步检索 |
| **回声消除** | 免提时把自己的声音当用户输入 | 需要 AEC，硬件或算法 |
| **方言/口音** | 老年人说方言识别率骤降 | 选支持方言的 ASR，或加关键词纠错表 |
| **数字与专有名词** | 「A100」读成「A 一百」 | 建发音词典（TTS 侧） |
| **噪声环境** | 车间/大厅识别率低 | 指向性麦克风 + 降噪 |

> [!IMPORTANT]
> **语音项目的一条铁律**
>
> **首响 1 秒内的「填充语」比整体快 3 秒更有价值。**
> 「我查一下」这四个字能让用户感知的等待时间减少一半——这是体验设计，不是技术优化。

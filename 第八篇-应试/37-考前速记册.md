## 37.1 一、50 组易混点（左右对照）

| # | 别记成 | 正确 |
| --- | --- | --- |
| 1 | 一个词 = 一个 Token | 一个词可能拆多个 Token；1 汉字 ≈ 1 Token |
| 2 | 窗口大 = 知识多 | 窗口是单次输入上限，与知识量无关 |
| 3 | temperature 与 top_p 都调大 | 一般只调一个 |
| 4 | Embedding 就是向量库 | Embedding 是模型，向量库是存储检索系统 |
| 5 | 语义检索全面优于关键词 | 各有短板，需混合 |
| 6 | 微调能灌知识 | 微调改风格；知识用 RAG |
| 7 | 窗口够大就不需要 RAG | 每次付全量成本，中间内容易被忽略 |
| 8 | 分块越大越好 | 太大噪声多、成本高 |
| 9 | 重叠越多越好 | 10–20% 足够，多了冗余 |
| 10 | Top-K 越大越好 | 需重排收敛到 3–5 |
| 11 | 重排能救一切 | 召回没命中，重排无能为力 |
| 12 | 向量维度越高越好 | 更贵，需权衡 |
| 13 | 换 Embedding 直接替换 | 必须全量重建索引 |
| 14 | 上 RAG 就没幻觉 | 只能约束与兜底 |
| 15 | 有引用就一定对 | 引用可能张冠李戴，需校验 |
| 16 | Function Calling 是模型执行 | 模型只发请求，代码执行 |
| 17 | ReAct 轮次越多越聪明 | 多则慢且易死循环 |
| 18 | 多 Agent 一定更强 | 任务可拆才用 |
| 19 | 记忆越多越好 | 上下文膨胀、信息淹没 |
| 20 | 提示词越长越好 | 过长稀释重点 |
| 21 | 提示注入靠模型防 | 模型不是安全边界 |
| 22 | 私有化就合规 | 行为义务仍在 |
| 23 | 量化无损 | 精度损失 1–3% |
| 24 | 量化省显存 = 省 KV | 主要省权重 |
| 25 | 显存 = 权重 | 还要加 KV 与开销 |
| 26 | Docker = K8s | 打包 vs 编排 |
| 27 | 公有云一定便宜 | 量大时私有化更省 |
| 28 | POC 过就能上线 | 还要过安全、合规、性能 |
| 29 | 上线即结束 | 需运营与 Bad Case 闭环 |
| 30 | 证书 = 执业资格 | 职业能力培训证书 |
| 31 | 分块按字数切就行 | 结构化内容必须按结构切 |
| 32 | 表格可以按字数切 | 表格必须整表或按行+表头 |
| 33 | 元数据可有可无 | 决定权限、溯源、时效、增量 |
| 34 | 增量更新只插入 | 必须先删后插 |
| 35 | 权限可以检索后再过滤 | 会占名额、降质量、有泄露风险 |
| 36 | 评测只看答案像不像 | 要先看检索层指标 |
| 37 | 指标涨 1% 就是提升 | <1% 可能是噪声 |
| 38 | 一次改多个参数提效快 | 无法归因，必须单变量 |
| 39 | 微调不需要测试集 | 测试集参与训练会虚高 |
| 40 | LoRA 效果一定不如全参 | 接近全参，成本低得多 |
| 41 | 压测就是看极限 | 目的是找拐点 |
| 42 | 拐点后加并发能提吞吐 | 只会让所有人更慢 |
| 43 | 模型费是成本大头 | 实施与运维人力常更高 |
| 44 | 报价只报 Token 费 | 会漏算硬件、实施、运维 |
| 45 | 方案目标写「提升效率」 | 必须可验收（数字） |
| 46 | 范围只写做什么 | 必须写「不做什么」 |
| 47 | 实施计划只写我方任务 | 必须含客户配合事项 |
| 48 | 变更可以口头答应 | 必须评估 + 书面确认 |
| 49 | Agent 上线不用写应急预案 | 必须有回滚与熔断 |
| 50 | 内容标识只管对外网站 | 对内输出也可能需要 |

## 37.3 三、进场前 60 秒

```text
① 简答四段：背景 → 架构 → 步骤 → 风险
② 每段塞数字：参数、指标、成本
③ 每道都补两句：权限怎么控、降级怎么做
④ 单选遇绝对词：一定、全部、只能 → 多半错
⑤ 不会的题标记跳过，别耗时间
```

> [!tip] 最后一句
> 考的不是记忆力，是「你有没有真的想过这个系统怎么落地」。想清楚了，怎么问都答得出。

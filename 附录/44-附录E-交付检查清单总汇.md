## 44.0 怎么用这十张清单

全书散落着几十张清单，这一章把它们集中成**可以打印、可以逐项打勾**的十张表。用法三条：

1. **按阶段取用**，不要一次全打勾——清单是按项目时间线排的。
2. **每项后面括号里是详述章节**，不确定标准就跳过去看那一节。
3. **「否」不一定是错，但必须有理由**。评审问起时，你要能说出为什么跳过。

| 清单 | 用在什么时候 | 项数 |
| --- | --- | --- |
| 44.1 立项前 | 要不要接这个项目 | 12 |
| 44.2 需求与约束 | 第一次现场调研后 | 14 |
| 44.3 数据工程 | 数据摸底与入库 | 14 |
| 44.4 选型与容量 | 写方案的技术章节 | 12 |
| 44.5 安全与护栏 | Agent / 写操作上线前 | 12 |
| 44.6 评测与门禁 | 调优结束、准备上线 | 10 |
| 44.7 上线日 | 上线当天 | 10 |
| 44.8 合规交付 | 交付前一个月 | 12 |
| 44.9 验收与移交 | 验收会前一周 | 12 |
| 44.10 投标废标 | 投标文件封标前 | 12 |

## 44.1 立项前清单（12 项）

- [ ] 能一句话说清「现在的问题值多少钱」（20.3）
- [ ] 知道真实立项触发点（是「提效」还是「事故/断层」）（27.2）
- [ ] 已确认预算量级与决策人是谁（20.2）
- [ ] 已确认这是「懂且要做 / 懂但暂不做 / 不懂但要做 / 不懂也不做」哪一类客户（18.8）
- [ ] 有至少一条「最坏情况」的测算，敢讲给客户听（20.3）
- [ ] 已初步判断数据能否出内网（8.1）
- [ ] 已初步判断是否有强制合规等级（25.1）
- [ ] 已确认项目周期与客户的关键时间点（如上级检查、大促、开学）（19.10）
- [ ] 已识别是否存在隐性阻碍者（20.2）
- [ ] 已想清楚「本期不做」的边界（17.2、32.2）
- [ ] 已评估自身交付能力（人月、行业经验）（19.9）
- [ ] 已算过一个粗毛利的量级（低于 25% 建议不接）（43.6）

> [!warning] 这一张最容易「全打勾但都是猜的」
> 每一项都要有**来源**：谁说的、哪份文件、哪个数字。没有来源的打勾等于没做（20.8 决策台账）。

## 44.2 需求与约束清单（14 项）

- [ ] 谁在用（岗位、人数、年龄段、是否戴手套/在噪声环境）（17.2、27.3）
- [ ] 用在哪一步（是替代某一步，还是新增一步）（17.2）
- [ ] 现在这一步怎么做、一天多少次、一次多久（17.2）
- [ ] 答错一次的代价是什么（决定拒答策略与准确率目标）（27.3、28.2）
- [ ] 数据能不能出内网、能否上公有云（8.1、24.5）
- [ ] 文档总量、类型分布、扫描件比例（9.10）
- [ ] 是否有强标识符（型号/条号/编码/单号）（27.4）
- [ ] 内容是否多版本、有无生效日期（28.3）
- [ ] 权限粒度要到文档级还是块级（28.3）
- [ ] 是否需要写操作、写操作的最大金额/影响面（29.2）
- [ ] 用户是否会恶意使用（公开场景、学生、外部客户）（32.3）
- [ ] 硬件现状与限制（卡型、显存、机柜功率、是否信创）（30.3）
- [ ] 可接受的首响与端到端延迟（27.3）
- [ ] 客户侧能投入的人力（标注、抽检、验收判定）（19.9）

> [!tip] 这张清单的用法
> 打印出来带去现场，逐条问。**问完这一张，你的方案骨架就出来了**——因为每条约束都对应一个设计反转（33.3）。

## 44.3 数据工程清单（14 项）

- [ ] 已完成文档清点与分类（含 owner 指定）（26.2）
- [ ] 已抽样 100 份试解析，估算真实工作量（19.10 W2–W3）
- [ ] 已区分文本型与扫描件，走两条流水线（9.9）
- [ ] 表格已按「每行能独立回答一个问题」展开（9.8）
- [ ] 跨页表、合并单元格、双栏、印章已处理（9.8）
- [ ] 页眉页脚/水印/页码已剔除（9.2）
- [ ] 结构已还原（标题层级、条款、步骤）（9.2）
- [ ] 分块按语义单元，结构化内容用结构感知切分（10.3、31.6）
- [ ] 步骤/条款/题目等原子单元未被切断（27.7）
- [ ] 元数据十字段齐全（型号、条线、密级、生效日、版本…）（9.3）
- [ ] 增量更新机制已设计（含删除与重命名处理）（9.4、31.7）
- [ ] 过期机制（expire_at + 降权 + 通知）已配置（26.3）
- [ ] 质量抽检已做（字符 ≥98%、结构 ≥95%、表格 ≥90%、重复 ≤2%）（9.5）
- [ ] 敏感信息脱敏抽检通过（零明文）（26.6）

---

## 44.4 选型与容量清单（12 项）

- [ ] 候选模型已按「合规 + 可控」做减法（8.1）
- [ ] 许可证已核对（商用、用户量、衍生模型约束）（8.4）
- [ ] 自建 50 题评测集已跑过（含 5 道该拒答的）（8.5）
- [ ] 得分率 ≥0.80 且幻觉率 ≤0.05，或已说明差距与补救（8.5）
- [ ] 显存已按「权重 + KV + 1–2 GB」算过（24.2）
- [ ] KV Cache 按目标上下文长度算过（24.8）
- [ ] 容量链条已倒推（日活 → QPS → 并发 → 卡数 ×1.3）（24.1）
- [ ] 已压测找过拐点，生产按拐点 ×0.8 配置（24.4）
- [ ] 装得下用副本、装不下才并行的判断已做（24.10）
- [ ] Embedding/重排/OCR 是否放 CPU 已评估（24.11）
- [ ] 限流、队列、超时、优先级已配置（24.12）
- [ ] 降级链（主 → 备 → 小 → 静态话术）已设计并演练（24.12、23.7）

> [!important] 这张里最容易漏的两项
> **KV Cache（24.8）** 与 **压测拐点（24.4）**。漏了前者，上线就 OOM；漏了后者，第一次遇到峰值就是事故。

---

## 44.5 安全与护栏清单（12 项）

- [ ] 有书面「不做清单」与越界拒答策略（13.7、32.2）
- [ ] 工具数量 ≤12 且已分组（14.8）
- [ ] 每个工具描述写了「何时用 / 何时不要用」（14.9）
- [ ] 写工具有幂等键，重复提交测试无副作用（14.4）
- [ ] 写操作按 L0–L3 分级，L3 强制人工审批（15.5、29.5）
- [ ] 有最大轮次、单节点 Token、整体超时、工具调用次数上限（16.3）
- [ ] 工具返回内容与指令已隔离（防间接注入）（15.8）
- [ ] 最小权限：只读账号、出口白名单、文件系统隔离（15.9）
- [ ] 状态以工具返回码为准，不以模型声称的为准（13.12）
- [ ] 全链路 trace 可还原「看到什么 / 决定什么 / 做了什么」（16.7）
- [ ] 红队 12 条已跑，高危项全部关闭（15.4、15.10）
- [ ] 审计日志留存满足行业要求（金融 ≥3 年）（28.5）

---

## 44.6 评测与门禁清单（10 项）

- [ ] 黄金集 ≥50 题，含六种类型（含应拒答题）（12.2、8.5）
- [ ] 标注人已确认，双人交叉校验（12.2）
- [ ] 四指标基线已记录（Recall / Precision / Faithfulness / Relevancy）（12.3）
- [ ] 每次改动只改一个变量，有实验记录（12.4、39.3）
- [ ] 显著性判断已做（差距 <0.05 不决策）（12.4、41.6 题 9）
- [ ] 评测集与训练/微调数据已隔离（12.10）
- [ ] 评测集有维护机制（月补 5 条、季换 10%）（12.10）
- [ ] 上线门禁阈值已写进文档（12.6）
- [ ] LLM 裁判与人工一致率 ≥85%（若使用）（12.8）
- [ ] 线上评测（点踩、拒答率、追问率）已接入（12.7）

---

- [ ] 上一版本可一键回滚，且演练过（23.10）
- [ ] 数据（索引/向量库）可回滚或可重建（31.7）
- [ ] 四个看板（可用性/质量/成本/数据）已就绪（23.8）
- [ ] 告警接收人与升级路径已确认（23.10）
- [ ] 降级链演练通过（24.12）
- [ ] 索引版本号已记录，增量任务已启动（9.4）
- [ ] 权限抽测通过（用低权限账号搜高密级内容）（26.6）
- [ ] 值班表已排，客户侧联系人已确认（23.10）
- [ ] 对外统一话术已准备（19.11）
- [ ] 内容标识已在前端、接口、元数据三处生效（25.7）

- [ ] 生成内容标识三处齐全（25.7）
- [ ] 日志留存期限满足等保/行业要求（25.7）
- [ ] 数据出境判断已走完判断树（25.10）
- [ ] 敏感信息脱敏抽检通过（26.6）
- [ ] 算法/服务备案是否需要已确认（25.2）
- [ ] 等保测评/密评的配合材料已准备（30.3）
- [ ] 用户告知与隐私政策已更新（25.2）
- [ ] 合同合规六条款已确认（数据权属、责任、退出…）（25.8）
- [ ] 整改记录表已建立（问题/依据/措施/验证）（25.11）
- [ ] 安全责任人与应急联系机制已明确（15.7）

## 44.10 投标废标检查清单（12 项）

- [ ] 营业执照/资质证书在有效期内（22.5）
- [ ] 类似业绩数量与金额满足要求，合同复印件齐（22.5）
- [ ] 财务指标达标（或已用联合体/母公司解决）（22.5）
- [ ] 原厂授权书已取得（用第三方模型/软件时）（22.5）
- [ ] 信用记录自查无失信（22.5）
- [ ] 投标函金额大小写一致（22.5）
- [ ] 所有需要签字/盖章处已完成（含骑缝章）（22.5）
- [ ] 密封袋/电子标书格式符合要求（22.5）
- [ ] 技术偏离表逐条响应，无遗漏（22.5）
- [ ] 负偏离已声明（隐瞒=废标风险）（22.5）
- [ ] 章节顺序与招标文件一致，标题措辞对齐（21.8）
- [ ] **由非编写人逐项复核一遍**（22.5）

> [!warning] 最后一条是重点
> 编写人看自己的标书会「自动补全」缺失的内容。**换一个人逐项打勾，能挡掉 80% 的形式性废标。**

## 42.7 七、十篇必读：一句话结论与工程含义

如果只读十篇，读这十篇。每篇后面那句「工程含义」比论文本身更有用。

| # | 论文 | 一句话结论 | 工程含义（你要做什么） |
| --- | --- | --- | --- |
| 1 | Attention Is All You Need (2017) | 自注意力可并行建模全序列依赖 | 理解「上下文长度 = 成本」的根源 |
| 2 | GPT-3 / Few-Shot (2020) | 大模型能靠示例学会任务，无需改参数 | 先试 Few-shot，再考虑微调 |
| 3 | CoT (2022) | 让模型写推理过程能提升复杂任务准确率 | 复杂任务提示词里加「先分析再结论」 |
| 4 | LoRA (2021) | 低秩增量即可近似全参微调 | 微调优先 LoRA，别全参 |
| 5 | RAG (2020) | 检索外部知识可显著降低事实性错误 | 知识问题用 RAG，不是微调 |
| 6 | Lost in the Middle (2023) | 长上下文中部信息被显著忽略 | 关键内容放首尾，或压缩上下文 |
| 7 | Passage Re-ranking with BERT (2019) | 交叉编码器精排远优于双塔 | 召回后必须加重排 |
| 8 | RAGAS (2023) | RAG 可拆成召回与忠实度等可测指标 | 上线前必须建黄金集与四指标 |
| 9 | ReAct (2022) | 推理与行动交替能显著提升任务完成率 | Agent 的基本循环就是 ReAct |
| 10 | Indirect Prompt Injection (2023) | 模型读到的内容会被当成指令执行 | 工具返回内容必须当「数据」隔离 |

> [!tip] 读论文的正确产出
> 读完一篇，写三行：**它解决什么问题 / 它的前提假设 / 我要付出什么代价才能用上**。
> 写不出这三行，说明还没读懂——这比读十篇摘要更有价值。

## 42.8 八、怎么读这些材料（给不同读者）

| 你是 | 建议 |
| --- | --- |
| 备考为主 | 只读标「必读」的 8 篇摘要 + 本书考点速记 |
| 要做项目 | 必读 + 各官方文档，重点看参数与限制 |
| 要写方案 | 综述类（RAG Survey）+ 法规 + OWASP，用于支撑论证 |
| 要带团队 | 全部通读，重点是评测与安全两节 |

> [!tip] 一句话
> 论文给你「为什么」，文档给你「怎么做」，实测给你「到底行不行」。三者缺一，方案就会站不住。
